## X/Twitter 离线阅读：去掉左右栏只留正文

- 修正了之前错误做法：单独建 `public/x-reader.html` 是脱离 app 的死文件，没法跟翻译流水线配合。已删除。
- 正确做法：改 `lib/translate/contentHelper.ts` 的 `markGlobalNoise`（x.com/twitter.com 分支），X 三列布局只保留 `primaryColumn`，移除左右栏：
  - 右栏：`[data-testid="sidebarColumn"]`（稳定 data-testid）直接标记 `data-fanyi-remove`。
  - 左导航：在顶层 `<header>` 内、与 `<main>` 平级；用结构定位"不在 main 内且含 `<nav>` 的 header"标记移除，避免依赖随语言变化的 aria-label（主要/Primary/…），也避免误伤 main 内的返回栏 header。
- 验证：单测 5 个全过（含"main 内 header 不误伤"用例）；用 `temp/x-origin-raw.html` 真实抓取页确认 header+sidebarColumn 被移除、primaryColumn 保留。
- 关键 DOM 事实（X 真实页面）：左导航在 `<header>`（main 之外），右 sidebarColumn 嵌在正文列内部，三者并非同一 flex 容器的兄弟节点。

## 集成点（重要）
- `prepareDocument` → `markGlobalNoise` 是 `/translate/*`、`/nvd/*`、`/openrt/*` 服务端路径与扩展 `/fanyi/page` 路径共用的入口（pipeline.ts `runTranslationPipeline` L321→L357）。改动对两条链路同时生效。
- 服务端直接 fetch X 拿到的 SPA 骨架通常无 `primaryColumn`（需浏览器 hydrate），所以离线/扩展路径（hydrated HTML）才有效——和 `diag-x-layout.ts`（CDP 抓取）工作流一致。
- 部署前需 `npm run build:lib` 重新编译（dist 当前是旧的）。

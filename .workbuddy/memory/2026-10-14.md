# 2026-10-14

## WorkBuddy/CodeBuddy CLI 接入方式性能实测（19:10-20:00）

目标：除 GUI 当前方式外，实测 docs 目录（cnb.cool/codebuddy/codebuddy-code/docs）里的其他接入方式，找出最快的。

### 四种方式实测结果

| 方式 | 启动 | 协议链路 | 认证 | 结论 |
|---|---|---|---|---|
| GUI（当前，WorkBuddy.app） | 0s（prewarm 池常驻） | — | OK | 唯一可用 |
| CLI `-p` headless 单发 | hang 45s 零输出 | — | 死锁 | 不可用 |
| HTTP API `--serve` + `/api/v1/runs` + SSE | 8s 就绪 | 全通（POST 冷 137ms / 热 23ms、13ms） | `AuthenticationRequiredError` | 协议通、agent 不可用 |
| agent-sdk headless（local-agent-service `/v1/chat/completions`） | 10s | 服务正常 | 502 + 401（12s/34s/28s） | 不可用 |

### 根因：非交互模式无法登录（设计死锁）

- `codebuddy --help` 的 Commands 里**没有 login 子命令**；错误提示里的 `/login` 是交互式 TUI 内的斜杠命令 → `-p` / `--serve` / agent-sdk 都拿不到凭证。
- 凭证不在：环境变量（当前会话 env 无 `CODEBUDDY_API_KEY` / `CODEBUDDY_AUTH_TOKEN`）、settings.json / `CODEBUDDY_CONFIG_DIR` 复用、macOS keychain（CodeBuddy/codebuddy/workbuddy 等 service 名均无）、`CODEBUDDY_SERVICE_PROXY_URL`（那是 hook 服务代理 `…/internal/hooks/services/invoke`，不是模型认证）。
- 唯一官方口子（docs/env-vars.md）：`CODEBUDDY_API_KEY`（`-p` 非交互模式始终使用）+ `CODEBUDDY_BASE_URL` + `CODEBUDDY_INTERNET_ENVIRONMENT=internal`（中国版）。需自备 key。
- GUI 会话无法被外部复用：当前会话 CLI 是 `--serve --port 0`，未暴露 REST 端口；GUI 进程只监听 MCP 代理端口（56678/56679/56689/56898），无 `/api/v1/health`。

### 踩坑

- macOS 无 `timeout` 命令、无 `date +%s%3N`（不支持 %N）→ 用 `perl -e 'alarm N; exec @ARGV'` + python 计时，否则耗时测量全错。
- `ps -E` 才能看进程环境变量；Bash 工具是 GUI CLI 的子进程，`env` 可直接读到它注入的全部 `CODEBUDDY_*`。
- `--auth none` 不生效（仍 401，要 Bearer 密码）；首个 serve 实例的密码会写进 `~/.codebuddy/settings.json`。

### 结论建议

要程序化接入 → HTTP API 最快（协议层开销 23ms 级，比 GUI 的模型往返小两个数量级），但必须先申请 API key；只想跑翻译 → 直接调模型 API，别绕 agent。
### 澄清：settings.json 里的 password 是网关门禁，不是账号登录态（20:10）

用户指出 `/Users/saga/.codebuddy/settings.json` 里就有 password（`x2kbssVOw7uEG4QG0uZ_W4REz7qpnd-o`）。实测确认它是**第一层**凭据，不是登录态：

- 第一层网关鉴权用这个 password **完全通过**：`POST /api/v1/runs` → 202 accepted；`GET /runs/:id/stream` → 200，SSE 正常推送 `message` + `done` 事件。
- 第二层模型调用认证仍然失败：SSE 事件的 `content.markdown` = `AuthenticationRequiredError: Please use /login command`。

即：**本地 API 门禁 ≠ 账号登录凭证**。后者不在 settings.json（GUI 的 `~/.workbuddy/settings.json` 也没有）、不在环境变量、不在 keychain、不在 Electron 数据目录（`~/Library/Application Support/WorkBuddy` 几乎是空的）。

补充坑：serve 启动时密码优先取环境变量 `CODEBUDDY_GATEWAY_PASSWORD`（GUI 注入，Bash 工具继承），所以我起的 serve 打印的是 `OFw2...` 而非 settings.json 里的 `x2kb...`；另外 SSE 端点漏带 `Authorization` 头会返回 401，容易误判成"没登录"。

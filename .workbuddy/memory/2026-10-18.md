## 功能：本机 Agent 每轮 token 消耗（费用口径）打通到扩展 UI

需求：检查 codebuddy 参数拿到每轮调用费用 → 加进 local-agent-service → 显示到 fanyi-extension。

### 实测结论（SDK 0.3.276 + CodeBuddy 网关，真实调用验证）
- Agent SDK `result` 消息带：`usage.{input_tokens, output_tokens, cache_read_input_tokens, cache_creation_input_tokens}`、`total_cost_usd`、`duration_ms`、`num_turns`。
- CodeBuddy 订阅模式 `total_cost_usd` 恒为 0 → 费用口径以 token 数为准，cost 仅 >0 时透出。
- 探针脚本坑：在 WorkBuddy GUI 注入的环境变量下，SDK 拉起的 CLI 会尝试绑定 127.0.0.1:56014 并 EADDRINUSE（Electron pid 占用）。用 `env -i HOME PATH(node目录在前)` 干净环境即正常。这可能解释部分「Workbuddy 返回了空内容」偶发故障。

### local-agent-service 改动
- 新增 `src/agents/usage.ts`：`TurnUsage` 类型 + `parseTurnUsage`（全 0/缺失 → null）+ `addTurnUsage`（合计）+ `summarizeTurnUsage`（含 totalInputTokens/totalTokens）+ `formatTurnUsageLog`。
- `workbuddyPool.runPrompt` / `workbuddy.queryWorkbuddyRaw` 从 result 捕获 usage 并返回。
- `runWorkbuddy` → `{ text, usage }`；`runWorkbuddyStructured` → `{ parsed, usage }`；`runWorkbuddyJson` 同理；runner 的 `runAgent/runAgentJson/runAgentStructured` → `{ result, usage }`（新增 `AgentRunResult<T>`）。
- 调用点更新：routes.ts（/v1/chat/completions 的 usage 字段现在填真实 prompt_tokens/completion_tokens）、literary.ts ×2（补 `formatTurnUsageLog` 日志）、contextGraph.ts（日志）、translationAgent.ts。
- 文档翻译 Run：每次初译模型调用发一条新事件 `model.usage`（含 batchIndex/requestId/model + usage 摘要）；`runUsageTotals` Map 按 runId 累计；`run.finished` / `run.failed` 带 `usage` 合计并清账。

### fanyi-extension 改动
- `documentAgentTrajectory.ts`：新增 `formatTokenCount`（≥1w 折 k）与 `usageDetailLine`；`model.usage` 标题「本次模型调用 token 消耗」、详情「输入 X · 缓存 Y · 输出 Z · 合计 T · 费用 $n · 耗时」；`run.finished` 详情加「累计 …」行；model 筛选包含 `model.usage`。历史事件无 usage 时不渲染 0。
- `DocumentAgentWorkspace.vue` eventLabels 加 `model.usage: 'token 消耗'`（该面板的 eventSummary 会自动展示 usage 数值字段）。
- 未给网页文本翻译路径加 UI（chunk 粒度展示会刷屏）；该路径的 /v1/chat/completions 响应 usage 已是真值，客户端可自取。

## 修复「重新分析全书被翻译运行永久阻塞」

- 现象：点「刷新预处理状态 / 重新分析全书」提示"当前项目已有翻译任务运行…翻译结束后再启动预处理"。
- 根因：服务每次重启把 running/queued 孤儿运行标为 `paused`（error=服务重启后等待恢复），而服务端 `assertNoActiveTranslation` 与扩展端 guard 都把 `paused` 算作活跃 → 孤儿永不自行结束 → 整本书死锁（实测该项目积压 4 条 paused 孤儿）。
- 修复：`recoverInterruptedRuns` 改为把孤儿直接标 `failed`（resume 端点本就接受 failed，恢复能力无损，paused 只留给用户主动暂停）；另加幂等迁移把旧 `paused AND error='服务重启后等待恢复'` 转 failed。扩展端 guard 文案带上实际状态并指路 Agent 面板恢复/取消。
- 已重启服务，4 条存量孤儿全部迁移为 failed；两端 typecheck + 测试全绿（service 168 例，扩展相关 10 例）。

### 实测结论（SDK 0.3.276 + CodeBuddy 网关，真实调用验证）

## 修复「重新分析全书被翻译运行永久阻塞」

- 现象：点「刷新预处理状态 / 重新分析全书」提示"当前项目已有翻译任务运行…翻译结束后再启动预处理"。
- 根因：服务每次重启把 running/queued 孤儿运行标为 `paused`（error=服务重启后等待恢复），而服务端 `assertNoActiveTranslation` 与扩展端 guard 都把 `paused` 算作活跃 → 孤儿永不自行结束 → 整本书死锁（实测该项目积压 4 条 paused 孤儿）。
- 修复：`recoverInterruptedRuns` 改为把孤儿直接标 `failed`（resume 端点本就接受 failed，恢复能力无损，paused 只留给用户主动暂停）；另加幂等迁移把旧 `paused AND error='服务重启后等待恢复'` 转 failed。扩展端 guard 文案带上实际状态并指路 Agent 面板恢复/取消。
- 已重启服务，4 条存量孤儿全部迁移为 failed；两端 typecheck + 测试全绿（service 168 例，扩展相关 10 例）。

## 修复「浏览器连不上 127.0.0.1:8789，curl 却正常」

- 根因：18:04 修死锁时用 WorkBuddy 沙箱 shell `nohup` 起的服务进程，沙箱内 curl 探活 200，但沙箱外（浏览器扩展的 fetch）连不到它监听的端口 → 扩展报「无法连接本机服务…Failed to fetch」，且服务日志 18:04 后零请求。
- 修复：杀掉沙箱进程，用 dangerouslyDisableSandbox + nohup + disown 非沙箱重启（PPID=1，等效用户终端启动）；探活 200。
- 教训：给用户长驻服务必须用非沙箱方式启动；沙箱内 nohup 的进程对外不可达且随会话回收。

## 「点击翻译一直没有反应」排查

- 服务端健康：扩展来源 OPTIONS 预检 204 + ACAO 回显，GET /api/documents/projects 200；context-graph run completed（v5-language-pinned，revision f99d06d0），无活跃/挂起运行。

- 真问题（体验缺陷）：翻译/强制重译按钮被 `translationBlockedByPreprocessing` 静默禁用，点击无任何反馈。

## 修复「Run 卡在 running、批次初译永久挂起」

- 现象：UI 显示「workspace Agent：running」，服务日志停在 `模型调用开始 · 初译 批次 1`，之后既不返回也不报错；上一轮 run 2b346da2 同样卡在批次 1，而批次 2 正常（28s）。
- 根因：`WorkbuddySessionPool.runPrompt` 的超时只调用 `session.interrupt()` 并置 `timedOut`，但 `for await (session.stream())` 在 CLI 不响应中断/事件流已断时永不结束 → Promise 永久悬着，180s 超时形同虚设。
- 修复：抽出 `runSessionTurn`，用 `Promise.race([turn, timeoutPromise])` 让超时成为权威判定；超时即 dropSession（下一轮换新 CLI 进程）并抛「Workbuddy 调用超时」。补回归测试（stream 永不结束 → 120ms 内报错且 close 被调用一次），service 180 例全绿。
- 顺带确认：用户终端另起的服务进程（pid 7854）根本没绑上 8789（端口被我 19:10 起的 96776 占着），所以它只有启动日志、不处理请求。

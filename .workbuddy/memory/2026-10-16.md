# 2026-10-16

## 只读诊断：fanyi-extension 长日志（InlineCss / stale mapping / network error）

用户要求「找到问题根源，先不要改代码」，全程只读排查 + curl 实测，未改动任何文件。

### 结论（四类问题，各自独立根因）

1. `[InlineCss] stylesheet count exceeds configured limit (24)` + `CSS snapshot is partial: inlined=24, failed=1, links=25`
   - 配额截断，不是网络故障。`inlineStylesheets.ts:40 DEFAULT_MAX_SHEETS=24`；`collectStylesheetLinks` 只多读 1 张用于探测超限；`failed` 初值 = `discoveredLinks.length - maxSheets`。
   - 注意 `links=25` 是 `maxSheets+1` 截断后的计数，真实张数可能更多。
   - 连带后果：快照被打成 `v2-partial` → 服务端 `cssInliner.ts:105` 只在 `v2-complete && 无残留 link` 时放行，partial 会重新尝试内联 → 大概率失败 → `applyReaderFallback` → 缓存页变成 Reader 模板。

2. `[InlineCss] https://cdn.oreillystatic.com/...css: Failed to fetch`
   - `fetchCssBundle` 用的是默认 CORS 模式的 `fetch`（`inlineStylesheets.ts:226`），跨域 CSS 响应没有 `Access-Control-Allow-Origin` 就抛 TypeError。`<link>` 加载 CSS 不受 CORS 约束，所以页面本身没问题，只有快照抓取失败。

3. `[ServerTranslation] block id mapping stale for b8/b17/...`（如 `block= What Jev was asked | server original= What JevJev was asked`）
   - 服务端 `pipeline.ts:885` 对短块走 `applyInlineTranslation`，产出 `.fanyi-inline-original` + `.fanyi-inline-translation`。
   - 扩展端 `getServerOriginalText`（`serverTranslation.ts:280`）直接取 `el.querySelector('.fanyi-original').textContent`，父块的这个 span 里嵌着子块的 inline 译文 → 拿到「原文+子块译文」的粘连串；子块译文恰与原文相同时就是 `JevJev`。
   - `isSameBlockText` 单向包含判定失败 → 该块判 stale 并跳过，整块译文丢弃。
   - 加剧：`prepareHtmlForServer` 只清理 `.fanyi-original` / `.fanyi-translation`，不清理 `.fanyi-inline-*`，重翻时残留会作为原文的一部分被缓存。

4. `[ServerTranslation] network error: Failed to fetch`（POST /fanyi/page）
   - 已实测排除的两项：
     - CORS 预检正常（OPTIONS 返回 204 + `access-control-allow-origin: *` + `allow-headers: content-type,x-session-id`）。
     - 请求体大小不是瓶颈：6MB / 20MB 的 POST 都能进到 Worker 并返回 400 `url is required`。
   - 因此是**服务端没给出 HTTP 响应**：CF 边缘超时（大页面 + 85 块 → 流水线串行多轮 LLM 超过边缘等待窗口）或 Worker 超限被杀，CF 返回的错误页不带 CORS 头，浏览器统一报 TypeError: Failed to fetch（statusCode 0，服务端错误信息全丢）。
   - `translateViaServer` 的 fetch 没有 AbortSignal，用户只能干等到 CF 放弃。

### 待用户确认的一点
第 4 条需 DevTools → Network 看该 POST：若 Timing 里 stalled ~100s 后失败 = 服务端超时；若瞬间失败 = 页面 CSP connect-src 拦截（同一页面的 `/fanyi/page/check` GET 也会被拦，但那条失败被 `translation.ts:258` 静默吞掉，不会显示给用户）。

### 修复方向（未实施）
- 快照：partial 时不要只留 1 张 link，或放宽 maxSheets；跨域 CSS 抓取失败可考虑降级保留原 link 而非计 failed。
- `getServerOriginalText`：取原文时应剔除 `.fanyi-inline-translation`（和 `.fanyi-translation` 一样）。
- `prepareHtmlForServer`：补清 `.fanyi-inline-original` / `.fanyi-inline-translation`。
- `translateViaServer`：加 AbortSignal 超时 + 失败文案区分「服务端超时」与「请求被拦截」。

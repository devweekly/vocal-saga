# 2026-08-12 工作日志

## 对齐 fanyi-extension 的 404media 修复（vocal-saga）
- 用户追问 "vocal-saga 不需要修改么？" —— 关于此前在 fanyi-extension 做的 Readability 主条件化 + 404media walker 修复。
- 结论：
  - **Readability 主条件化不需要移植**：vocal-saga 的 `selectBestRoot` 已是多 provider 管线
    （siteRule/selector/density/**readability** 并行竞争，统一 scorer 评分，`scoring.ts` 给
    readability 候选 +0.05 强先验 boost）。Readability 本来就是主候选，不像 fanyi-extension 旧版那样仅作 fallback。
    旧 `detectArticleRoot` 的 `useReadability` fallback 仅被 densityProvider 以 `{useReadability:false}` 调用（已关闭）。
  - **walker 的 has-sidebar 修复必须移植**：vocal-saga 的 blockExtractor 是独立副本，缺 fanyi-extension
    那处修复。实证测试（`/tmp/p.html` 结构）证明 vocal-saga 服务端 `/force/` 路径翻不出 404media 正文
    （只提取 hero 区域 3 块，正文三段全丢）。
- 根因（vocal-saga）：`selector.ts` 的 `chooseBestRoot` 把 root 从 `.post__content` 上提到 `<main>`
  （`<main>` 含兄弟 `.post-hero` 的 h1，评分 16.8 最高）→ walker 从 `<main>` 起走，遇到子节点
  `<article class="... has-sidebar">` 被 `shouldSkipByClass` 命中 `sidebar` 整棵 `FILTER_REJECT` → 正文丢失。
  （注：vocal-saga 的 `selector.ts` 已含 `.post__content` 选择器，不缺选择器，只缺 walker 修复。）
- 修复 `lib/translate/blockExtractor/walker.ts`：噪声类跳过（含 `shouldSkipByClass`/`shouldSkipBySiteRules`）
  命中时，若 `tag==='article'||'main'` 则改为 `FILTER_SKIP`（跳过自身、下钻子树），与已有 metadata 守卫的
  article/main 特例一致；div/section 不豁免（避免 ad-content 等噪声 div 被下钻）。
- 验证：新增 `tests/extraction-404media.test.ts`（真实 404media DOM 结构），修复后 8 块、正文两段均在；
  全量 `1140 passed`（47 文件）；`tsc --noEmit` 通过。
- 注：改动在 `lib/` 源码，需 `npm run build:lib`（deploy:cf）重新编译 `lib/dist` 并部署才上线；
  wrangler OAuth 此前在非交互环境过期，部署需 `CLOUDFLARE_API_TOKEN` 或 `wrangler login`。

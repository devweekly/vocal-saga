# 2026-09-08

## /translate/<url> 命中 D1 缓存却返回 403/500（openai.com）

现象：`https://s.sunxiunan.com/translate/openai.com%2Findex%2Fresearch-acceleration-view-inside-openai%2F`
返回 `{"error":"fetch ... failed: HTTP 403"}`，但 D1 `translations` 表里 id=608 明明存着
2.38MB 的完整译文（60 处 fanyi-translation，59 处非空）。

根因（两道门都卡住）：
1. `isHealthyCachedHtml`（lib/app.ts）要求字面量 `<html`，过严 —— 旧 pipeline 产物是
   `<!doctype html>\n<body ...><head><base …>…`，`<body>` 在 `<head>` 前且**没有** `<html>` 包裹。
2. 即便绕过 1，`validateTranslationCompleteness` 里也有 `html.includes('<html')`，照样判 unhealthy。
→ 缓存 miss → 重新 fetch 源站 → openai.com 现在 403 → 500。

修复：
- 新增 `hasDocumentRoot(html)`（lib/translate/translationValidator.ts，已导出）：
  `doctype html` 或 `<html>` 满足其一即可。app.ts 与 validator 统一调用它。
- `isHealthyCachedHtml` 提到模块顶层并 `export`（原先是 createApp 内部私有函数、零测试覆盖）。
- `handleTranslateRequest` 新增**陈旧缓存兜底**：把 D1 行提到 try 外（cachedRow），
  translateUrl 抛错时若有旧译文就返回 200 + `X-Translate-Source: d1-stale-fallback`
  + `X-Translate-Warning: <错误>`；没有旧行才返回 500。

验证：线上已返回 200 且 `x-translate-source: d1-cache`（脚本剥离后 2.38MB→238KB，属正常）。

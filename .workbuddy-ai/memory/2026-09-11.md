## 测试套件跑不起来 / 太慢 —— 根因是本机文件读取

**症状**：`npx vitest run` 里 62 个测试文件全部报
`[vitest-pool]: Failed to start forks worker ... Timeout waiting for worker to respond`，
整套跑 400s+ 后 0 个文件成功。

**根因（环境，不是代码）**：
- 本机每次文件 `read` 约 **80ms**（`fs.statSync` 是 0.02ms，说明是 read 被安全代理/
  EDR 之类拦了）。测法：读 50 个 parse5 文件 = 4.0s。
- vitest worker 启动超时是**硬编码**的 `START_TIMEOUT = 6e4`（见
  `node_modules/vitest/dist/chunks/cli-api.*.js`），不可配置。
- jsdom 模块图 ~900 个文件 → 冷启动 50~66s → 必然超过 60s → 每个文件都超时。
- 定位方法：`node -e "import('jsdom')"` 计时（50~66s），
  对比 `--environment=node` 跑单文件只要 407ms。
- 注意：本机负载会持续恶化。同一天内 `import('happy-dom')` 从 1.6s 涨到 **947s**，
  任何 node 进程都会被拖死（表现为命令 SIGTERM / 卡在 vitest banner）。

**修复**：`vitest.config.ts` 改成两个 project（vitest 4 已移除
`environmentMatchGlobs`，替代方案是 `test.projects` + `extends: true`）：
- `node` project：52 个不依赖 DOM 的文件，`environment: 'node'`，启动 ~0.4s
- `dom` project：10 个用全局 `document`/`window` 的文件，`environment: 'happy-dom'`
  （`happy-dom` 本来就已经写在 package.json devDependencies 里，只是没装）

顺带：删掉两个遗留的临时验证脚本 `tests/_verify.tmp.test.ts` / `_verify2.tmp.test.ts`
（它们读已经不存在的 `/tmp/a601.html`、还依赖 playwright；未被 git 跟踪）。

**未完成验证**：改完配置后本机已慢到连 `--project node` 都起不来 worker，
所以这次改动**没有跑通完整测试**。等机器恢复后需要：
`npx vitest run`（预期 52+10 全部跑起来），重点看 `tests/redirectGuard.test.ts`。

## redirectGuard 守卫脚本

`lib/redirectGuard.ts` 的 fetch guard 现在同时 patch `window.fetch` 和
`globalThis.fetch`（裸 `fetch` 走的是 globalThis，与 window.fetch 不是同一引用），
否则相对路径会抛 `ERR_INVALID_URL`、绝对路径会走真实网络导致测试超时。

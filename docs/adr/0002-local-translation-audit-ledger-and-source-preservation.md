# ADR-0002: 本地翻译全流程审计账本与原始来源保全

- 状态：Accepted
- 日期：2026-10-18
- 适用范围：local-agent-service 的全部翻译、审校、预处理、质量审计、返工与采纳流程。
- 相关决策：[ADR-0001](0001-unified-local-translation-context-delta.md)

## 背景

最终译文和事件摘要无法回答某段原文如何被翻译、重试输出是什么、Reviewer 看到了什么、为什么产生某项修订，也无法还原模型调用失败时已取得的证据。原始文件与解析后的段落文本不同；只有段落文本不能精确还原 EPUB 资源、HTML 结构或 PDF 原件，只有路径或哈希也不代表原件已保存。

## 决策

### 1. 持久化账本是事实来源

所有会影响结果、运行状态、证据或用户决策的动作必须写入本机持久化存储。终端日志、SSE/HTTP 事件和 UI 状态只能作为投影，不能是唯一记录。记录应尽可能通过 projectId、sourceRevisionId、runId、segmentId、batchIndex、attempt、stage、requestId 关联，包含时间、状态和错误。历史采用追加式记录；重试、修订、人工采纳不能静默覆盖旧证据。

### 2. 原始来源必须保全

- 导入原始文件时，必须把原始字节保存到服务管理的数据目录，并记录文件名、格式、字节数、SHA-256、保存路径和导入时间；不能依赖浏览器临时文件或上传临时目录。
- 每个来源版本都必须持久化完整解析后片段原文、稳定 ID、ordinal、章节/路径、页码及结构元数据。
- 若入口只提供片段而没有原始文件，必须显式标记为 segments-only / sourceFileSaved=false，不得声称原件已归档；片段原文仍须完整保存。
- 原件哈希、片段数或读取校验失败时，必须显式报告。清理缓存、重试、重新预处理和采纳译文不得删除原文证据。
- 来源版本变更应产生新版本并保留旧版本，除非用户明确执行数据清理。

### 3. 每一次模型调用都要记录

初译、缺失片段重试、准确性/术语 Reviewer、人物声音/文风 Reviewer、全书分析及质量返工相关调用，都必须有独立账本记录，至少包括：

- 调用 ID、父 Run/批次/片段 ID、阶段、尝试序号、开始/结束时间、耗时、Provider、实际模型、Session scope、状态、错误和重试关联；
- 实际 system/user prompt、结构化输出 schema、输入片段 ID、当次 TranslationBrief、上下文/记忆版本和配置指纹；
- 运行时能提供的原始响应及解析后的结构化响应。若仅能取得解析后结果，必须标明响应形态，不能声称保留了原始传输字节；
- JSON/结构/ID/规范译名标记验证结果，缺失、重复、未知 ID 和拒绝原因；
- 失败时保留已取得的输入、部分响应、异常类型和错误；不能只留下最终通用错误。

审校输入必须能还原对应原文和被审校的初译/候选译文。审校原始输出、finding、证据、修订建议和修订候选都要保存；“审校完成/发现 N 项”不算完整记录。

### 4. 片段历史必须可重建

对任一片段，应能按时间顺序还原原文、每次初译/重试输出、每轮 Reviewer 输入输出和 findings、每个自动修订候选及父候选、当前候选、已采纳译文、人工修订，以及接受/拒绝/返工等状态变化。translation_results 和 review_findings 只是结果投影，不能代替逐次调用账本。

### 5. 上下文和 Prompt 必须版本固定

每次调用都绑定来源版本、Prompt revision、Pipeline/策略版本、模型、语言方向和实际上下文快照。文学模式需保留 TranslationBrief 的实际内容、Context Graph/记忆版本和上下文哈希；仅保存哈希、字符数或摘要不够。重试必须关联之前调用并保存本次独立输入输出。缓存不能替代账本或覆盖人工修改。

### 6. 重要状态转换必须留痕

包括项目创建、原件导入、重新解析、来源版本切换、预处理阶段、Run 排队/启动/暂停/恢复/取消/失败/完成、批次调度、模型调用、重试、候选保存、审校、人工编辑、采纳/拒绝、质量审计/返工、导出和清理。失败的持久化操作不能只写控制台；已发生的调用和部分结果必须在取消或崩溃后仍可查询。

### 7. 设置页显示实际本机路径

服务提供不含密钥的受限诊断接口，返回运行时实际数据目录、主数据库、项目目录、工作目录、环境文件路径（可确定时）、正文存储开关和原件保全状态。扩展 Setting 页展示服务返回的真实路径，不在 UI 中猜测 home 目录。服务离线时显示“暂不可读取”，不得显示猜测值。不得返回 Token、API Key 或完整环境变量。

### 8. 保留失败必须显式

默认优先保留原文、调用输入输出、审校结果和状态事件。可通过压缩、有界批量写入和索引优化性能，但不得靠截断文本、仅保存摘要或自动清理历史来伪装完整审计。若存储空间/大小限制导致审计写入失败，当前动作必须标记为审计不完整并向调用方报告，不得把未持久化结果标记为成功。凭据和认证头永不保存；清理功能必须区分缓存、请求历史、项目原文与审计账本。

## 验收

- 原始文件可读回且 SHA-256 一致；segments-only 项目明确报告原件未保存。
- 一段文本经过初译、定向重试、两类审校、修订和人工采纳后，可按顺序查询每次调用输入/输出、校验、finding 和各版译文。
- 模拟模型异常、截断响应、存储失败、取消和服务重启，验证历史证据不消失、不被覆盖。
- Setting 页路径与服务运行时解析路径一致，且不泄露凭据。
- CI 覆盖迁移、旧数据库兼容、账本写读、原件校验和路径接口。

## 后果

本决策增加磁盘占用和写入量。完整性优先于少量存储与日志成本；性能优化应采用压缩、分层存储和索引，不得省略原文或调用历史。

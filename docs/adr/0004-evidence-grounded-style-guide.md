# ADR-0004：全书文风基准采用分维度、可审阅的分析契约

- 状态：Accepted
- 日期：2026-10-20
- 相关组件：`local-agent-service` Context Graph、`fanyi-extension` LiteraryMemory 编辑器、TranslationBrief

## 背景

全书预处理当前只产出 `narrativeStyle` 与 `styleRules`，但扩展中的 `LiteraryStyleGuide` 已定义叙述声音、语域、节奏与句法、对白特征、措辞与词汇、规则、避免项等字段。后端 Schema、持久化和状态 DTO 未覆盖这些维度，导致 UI 中多数字段长期为空。现有全书采样同时服务实体/人物识别与文风分析，且偏向名称线索，无法保证各文风维度都有足够证据。

## 决策

1. Context Graph 的全书文风输出应使用显式、版本化的分维度契约：叙述声音、语域、节奏与句法、对白特征、措辞与词汇、规则建议、避免项。空值允许表达证据不足，不得为了填满表单而臆造。
2. 观察性描述与规范性建议必须区分。叙述声音、语域、节奏、对白、措辞描述应基于抽样原文；规则是供用户审核的翻译建议；避免项只有在原文证据或明确用户偏好支持时才提出，不得凭空推断。
3. 每个文风维度应尽可能携带可核验的原文证据引用（源 segment ID 与短引文）。证据只能引用本次模型调用实际看到的原文样本；无法提供证据的内容应保持空白或标记为低置信度候选。
4. 后端必须完整持久化并在状态 DTO 中返回各维度，扩展必须按字段映射到既有 `LiteraryStyleGuide`。导入后仍是候选状态，必须由用户确认才能注入后续翻译和 Reviewer 的 TranslationBrief。
5. 不得将未确认的全书文风直接注入 TranslationBrief，也不得绕过现有原文版本、时间边界与证据验证。Context Graph 全局文风是跨章节总结，不应取代按当前批次时间边界筛选的证据化上下文。
6. 文风采样应与实体/人物采样目标区分，并通过独立的采样理由与覆盖诊断评估叙述、对白及早中晚章节覆盖。样本预算应有界，优先复用已有样本，但不能让实体候选长期挤占所有文风样本。
7. 修改分析 Schema、提示词或持久化语义时必须提升 `CONTEXT_GRAPH_ANALYSIS_VERSION`，让旧分析能被识别为过期并显式重新分析；不可静默将旧结果当作已满足新契约。

## 后果

- 前后端需要同步升级 Schema、存储、状态 DTO、导入映射及测试。
- 旧版预处理结果需要按新分析版本重新运行，旧数据不得被误认为已生成所有维度。
- 个别字段在证据不足时仍可能为空，这是正确行为；质量评估应关注证据覆盖与有用性，而不是填充率。
- 保留人工确认机制，避免未经审核的风格推断影响整本译文，并保留审计与可回溯能力。

## 验收标准

- 七个维度都能从模型输出流经持久化、状态 API、扩展表单和 LiteraryMemory。
- 空字段不会被伪造默认文案填充；规则和避免项能正确处理多行列表。
- 新旧分析版本可区分；重新分析后能获取新维度。
- 候选文风不会进入 TranslationBrief；确认后的文风可被初译和两类 Reviewer 共享。
- 测试覆盖全字段映射、旧数据兼容、证据边界和确认状态。
